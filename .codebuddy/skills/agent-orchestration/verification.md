# 验证与复核（agent-orchestration）

## 契约引用
> 任务 ID、状态、字段、回交五项、路径根、工具口径与派单模板**只以主文件 [SKILL.md](~/.workbuddy/skills/agent-orchestration/SKILL.md) 为准**（唯一副本，本文件不复制）。
> 路径根 = `${WORKSPACE}`（当前工作区）；项目内文件一律写作 `${WORKSPACE}/.codebuddy/...`。

## 1. 集成检查清单（每任务回交后逐项过）
| # | 检查项 | 做法 / 通过标准 |
|---|---|---|
| 1 | 交付物存在 | 声明路径的文件/产物实际落盘 |
| 2 | owns 一致 | `git diff --stat` 的改动 ⊆ 声明 `owns`，且 ⊄ `forbid` |
| 3 | 无重叠写 | 两任务改动文件集合交集为空 |
| 4 | 共享接口对齐 | 调用方与提供方签名/契约一致，编译通过 |
| 5 | 针对性验证 | 只跑与本任务 `verify` 相关的最小验证集 |
| 6 | 跨任务集成 | 合并后整体构建/测试通过，非各任务自测之和 |

## 2. 风险分级复核
| 改动级别 | 复核方式 |
|---|---|
| 琐碎单文件 | 主代理按上表自查即可，**不派审查代理** |
| 实质改动 | 按三类分开评估：需求符合性 / 实现质量 / 跨模块集成 |
| 高风险（跨模块/共享接口/并发） | 三类按风险决定是否派独立复核代理 |

> 原则：**不为每个小改动造审查代理**；复核代理只用于风险确实需要独立视角的实质改动。

## 3. 失败处理
`定位具体失败（哪条验证/哪个文件）→ 判归属（本任务 / 依赖 / 共享资源）→ 建窄修复任务 → 只重跑相关验证 → 证据保留 → 共享问题升级主代理`。
- 窄修复任务必须写明：写集合（`owns`/`forbid`）、验收条件、仅重跑相关验证项。
- **禁止**「修到全绿为止」等无界指令；重试**上限 3 轮**，第 3 轮仍失败即停并升级，不自动扩范围。
- 失败证据（日志摘要、复现命令）随回交五项保留供定位，不写入 TASK_GRAPH 结论列。

## 4. 证据分级（本项目既有）
`隔离夹具 ≪ 图形客户端 ≪ 真实多人`（弱 → 强）。
- 只写实际跑到的层级；**未测不得称已验证**；低层级通过不得表述为高层级通过。
