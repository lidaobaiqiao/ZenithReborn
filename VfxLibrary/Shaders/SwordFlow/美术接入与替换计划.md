# 自有剑流材质与逐步替换

用户已明确要求自行控制着色器与资源，覆盖此前“优先复用现成材质”的方向。复用游戏引擎和标准编译工具不等于把现成材质改名为原创；每次替换要分别说明源码、贴图和动作的来源。

0.3.59第一阶段：`ZRSwordFlow.fx`是项目自行编写的独立带面着色器，直接使用路程／宽度坐标；没有复制或包含OniCrimsonSlash实现，也没有将旧编译文件改名。默认慢色场与噪声由数学运算产生，不使用外部美术。程序化效果仍是第一版视觉候选，不视为用户已认可。

## 美术接入约定

库中按大类、实际剑名存放，例如：

- `ColorFields/SwordTrail/TerraBlade/color.png`：慢底色色场，RGB负责颜色，透明度不定义形状。
- `Masks/SwordTrail/TerraBlade/active.png`：RGBA动态蒙版图集，Alpha负责形状；不把底色烘进蒙版。
- 圆环与粒子继续独立放入`Masks/Rings/剑名`与`Masks/Particles/剑名`。

游戏内对应资源放在`ZenithReborn/Assets/Vfx/ColorFields/SwordTrail/剑名/`与`ZenithReborn/Assets/Vfx/Masks/SwordTrail/剑名/`。通过`Assets/Vfx/Materials/SwordFlow/bindings.json`绑定，避免改轨迹代码。下面是尚未启用的填写示例；当前实际配置为空，素材缺失时不应直接启用这些路径。

```json
{
  "schemaVersion": 1,
  "weapons": {
    "TerraBlade": {
      "colorField": "ZenithReborn/Assets/Vfx/ColorFields/SwordTrail/TerraBlade/color",
      "motionMask": "ZenithReborn/Assets/Vfx/Masks/SwordTrail/TerraBlade/active",
      "frames": 16,
      "columns": 4,
      "loopSeconds": 1.2
    }
  }
}
```

底色图请保持Alpha全不透明，避免加载时的预乘处理影响RGB。路径不写扩展名。原版武器使用稳定英文物品名，模组武器使用`模组名/物品名`。图集从左到右、从上到下排列；横向是新剑头→旧尾，纵向是亮刃→暗侧。每帧尺寸一致，建议边界留透明像素；采样会向内缩半个纹素避免串帧。未绑定的单项使用程序默认值；绑定动态蒙版后，其Alpha替代程序轮廓，不再被默认轮廓裁切。

当前没有真实美术输入，因此实际素材的尺寸、循环接缝与轮廓配准仍需随素材到位逐剑验收。接口准备完成不等于逐剑美术已经完成。

## 可重复编译与来源

`checks/compile_effects.py`调用开发机已有的微软D3DCompile，输出FNA可读取的Effect；编译器不打进模组，玩家不新增依赖。`checks/run_wood_checks.ps1`已纳入此步骤。源码和编译结果的SHA256登记在`Assets/Effects/build-manifest.json`，打包时逐项核对。

接口依据：[FNA Effect编译说明](https://fna-xna.github.io/docs/2b:-Building-New-Games-with-FNA/)，[微软D3DCompile接口](https://learn.microsoft.com/en-us/windows/win32/api/d3dcompiler/nf-d3dcompiler-d3dcompile)。这些用于标准接口与工具调用，不是材质源码来源。

`checks/run_soul_trail_render.ps1 -WithoutThirdParty`生成只用于隔离测试的无第三方资源包；`checks/verify_own_effect.py`核对相同生产DLL、资源确实移除、零美术输入及两包逐帧画面完全相同。该试验只覆盖普通主飞剑，不代表其他旧路径也能移除资源运行。
