## 一、设计定义

**薄刃（Thinblade）**：第四道灵魂诅咒，替代原「阻隔（Barrier）」。

> 剑形犹在，锋芒已失。

每把飞剑生成时做一次有效性判定：Cursed 有效 70%、Weakened 90%、Released / Blessed 100%。残缺飞剑照常生成、飞行、消失，但**不能形成有效命中**。Boss 绑定不变：蜂王 → 世纪之花 → 石巨人。

**最终原则：保留剑的形态与运动，剥夺部分剑锋的杀伤力。**

## 二、替换了什么

| 项 | 原「阻隔」 | 现「薄刃」 |
|---|---|---|
| 负面效果 | 飞剑穿地形超过 32 / 64 像素即提前退场 | 部分飞剑无有效杀伤力 |
| 作用层 | 飞行途中的地形判定 | 生成时的命中资格 |
| 阶段 | Cursed / Weakened / Released / Blessed | 同阶段系统，四档全可达 |
| 用户可见名 | `Names[3]="阻隔"` | `Names[3]="薄刃"` |
| 祝福 | 穿界（破障） | **不变** |
| Boss 组 | `[Bee, Flower, Temple]` | 不变 |

## 三、关键实现决策

### 1. 枚举改名但整数位置不变

`SoulCurse.Barrier` → `SoulCurse.Thinblade`，**整数值 3 与其余五个成员的顺序、标识符全部不动**。

- 存档只持久化 `Seals`（18 位 Boss 位掩码）与 `LegacyReleased`（按 `1 << (int)curse` 的位），不存枚举名或枚举整数 → 旧档的蜂王 / 世纪之花 / 石巨人进度直接沿用，无需迁移。
- `Groups` / `Names` / `Blessings` / `BossNames` 全按整数索引；`SoulTraits.cs` 生成 `"curse-"+curse` 键、`SoulBossUnlocks.cs` 用 `Enum.TryParse` 解析，改名后自动自洽；全仓库无硬编码 `"Barrier"` / `"curse-Barrier"` 字符串。
- `SoulBlessings.cs` 两处 `BlessingTuning.Blessed(soul, SoulCurse.Barrier)` 只改标识符，穿界破甲链（`CrossedSolid` → `SoulBreach.Hit` → `BlessingTarget`）一行未动。

### 2. 这次四阶段全部可达，直接按 CurseStage 分档

`Groups[3]` 有 3 个 Boss，`StageForCount(count, total=3)` 得到 0 → Cursed、1 → Weakened、2 → Released、3 → Blessed。与上一轮偏锋组（2 Boss、Weakened 永不可达、被迫按 Boss 记录数分档）不同，这里概率可直接由 `soul.Curse(SoulCurse.Thinblade)` 取，无需另立口径。

`SoulThinblade.EffectiveChance(CurseStage)` 是概率的唯一来源；阶段说明文案也调用它，不另写一份数字。

### 3. 命中资格拦截，不用零伤害

`SoulBlade.CanHitNPC(NPC)` 开头按实例状态返回 `false`。这是唯一能同时挡住两处命中链的入口：

- `OnHitNPC`（约 `:294`）是五族唯一扇出点，还负责 `targetHits` 计数。
- `ModifyHitNPC`（约 `:339`）会经 `WoodCombat.Apply` 在命中阶段施加木质标记与 buff。

tML 语义下 `CanHitNPC=false` → `Projectile.Damage()` 整段跳过该 NPC → 不构造 `HitInfo`、不写 `npc.immune`、不调两个 hook → 伤害、命中特效、`targetHits` 命中次数、`oreHitUnits` 穿透次数、免疫时间全部天然不碰。这正是设计稿 §3.3 与 §6.6 要的「接触不形成实际命中事件」。

### 4. 残缺语义字段，避开初始化陷阱

字段取名 `ThinbladeDisabled`（true = 残缺），而不用设计稿建议的 `IsThinbladeEffective`。原因：`SoulBlade.SetDefaults()` 会把实例状态清零为 `false`；若字段语义为「有效」，未显式赋值的弹幕（夹具手工构造、网络包到达前的远端）会被误判成残缺。用残缺语义则默认 `false` 天然代表正常。

状态在 `SoulItem.EmitBlade` 生成时写一次，飞行期间不再变动；玩家中途解除诅咒只影响后续新生成的飞剑。

### 5. 多人同步复用偏锋已建好的范式

`SendExtraAI/ReceiveExtraAI` 末尾成对追加一个 bool（放在 `CurseOffset` 之后，不插到 `ConfigureReborn(reader.ReadBoolean())` 之前，避免打乱读序）；随机只在拥有者客户端 `EmitBlade` 掷一次，`netUpdate = true` 触发同步，`ReceiveExtraAI` 只读不重掷。

### 6. 地形惩罚移除，穿界祝福保留

- 删除 `SoulBlade.AI` 里 `SoulTerrain.Sweep(..., SoulCurses.TerrainAllowance(...), ref terrainDepth)` 的惩罚调用，以及只服务于它的 `terrainDepth` 字段与初始化。
- 删除 `SoulCurses.TerrainAllowance` / `TerrainAllowanceAtStage`（零引用）。
- **保留** `terrainArmed`、`SoulTerrain.SolidAt`、`SoulTerrain.Sweep` 函数本身（夹具仍测通用几何），以及 `Blessings.CrossedSolid(Projectile, previousCenter, Projectile.Center)` —— 穿界祝福靠 `terrainArmed` 门控，与已删的负面限制只是共用门控，没有逻辑耦合。

### 7. 视觉后置

设计稿 §5.3 允许「优先完成伤害机制，视觉表现作为后续改进」。探查确认改 `BladeOpacity` 只影响主剑本体、不影响剑影与拖尾，会做出不一致的半残状态；本轮不做视觉区分。
