# 0.3.2：四柱结束后的月亮领主召唤恢复

用户反馈：摧毁四柱后不出现提示，也没有月亮领主。当前实际启用的模组是HERO与天顶复苏0.3.1，日志没有召唤异常。

## 已核对的事实与边界

只读载入「测试.wld」的原版头部得到：四种天界柱均已击败、均不再激活，`LunarApocalypseIsUp=false`，`MoonLordCountdown=0`。世界也有历史月亮领主击败记录，因此不能根据“四柱曾经击败”就每次进世界都自动召唤。

核对当前实际运行的tModLoader.dll原版逻辑：`WorldGen.UpdateLunarApocalypse`在月亮事件标记为false时直接返回，既不启动倒计时也不发出提示；它不会只依据历史四柱击败旗标继续事件。这条故障路径已在隔离加载检查中复现。现存存档与日志无法追溯当时为何未开启事件标记，也不能据此断言是HERO造成的。

另确认原版世界头部保存了月亮事件/天界柱状态，却没有保存月亮领主召唤倒计时；只依靠原版字段无法保证倒计时跨退出继续。

## 修改

- 记录当前一轮实际出现、击败的四种天界柱。最后一柱完成后，如果没有存活柱、没有月亮领主、没有现成倒计时，则补上原版3600帧、约60秒的召唤倒计时和提示。
- 保留原版正在进行的倒计时，不每帧重置；继续使用原版倒计时到点召唤分支，没有替换Boss AI或掉落。
- 在本模组世界数据中保存待召唤的剩余时间。重进后继续剩余倒计时；实际观察到月亮领主后清除待召唤记录，避免击败后重复召唤。
- 还有存活天界柱时不补召唤；客户端不能自行启动服务器Boss；没人存活时等待有效玩家再恢复。
- 增加`/zmoon`查看状态、`/zmoon repair`明确修复已完成四柱但没有待召唤的旧世界。该修复需要四柱击败记录，不允许跳过未完成的四柱。

针对这次已确认故障的「测试」世界，在正式模组目录另存一份按世界GUID匹配的单次恢复请求。下次进入该世界且玩家存活、无存活天界柱或月亮领主时，恢复正常约60秒倒计时；成功后把请求归档为`.applied`。它不会应用到其他世界，也不会在之后每次进入时重复生效。
