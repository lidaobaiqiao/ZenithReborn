# 协作开发指南（多人同步）

状态：已实装（2026-11-05）。适用于「两人及以上共写同一仓库」。

## 0. 方案一句话

云端仓库 `https://github.com/lidaobaiqiao/ZenithReborn`（**公开仓库**）是唯一真源。
两人都从它拉取，各自在功能分支上改，PR 合回 `master`。
**不同步 `artifacts/`（约 16 GB 本地产物），不靠网盘/微信传代码。**

## 1. 给对方开权限

公开仓库任何人可 `clone`、可读；**`push` 需要授权**。二选一：

| 模式 | 适合 | 操作 |
|---|---|---|
| 协作成员（推荐） | 两人长期共写，互相信任 | `Settings → Collaborators → Add people` 输入对方 GitHub 用户名 → 对方查收邮件并接受 |
| Fork + PR | 只想让对交合并请求 | 对方 `fork` 到自己的账号，改完向 `master` 发 PR |

协作成员模式下**仍然走分支 + PR**：直接推 `master` 能推成功，但会绕掉 review 与回滚点。

## 2. 第一次上手（朋友机器，一次性）

```bash
git clone https://github.com/lidaobaiqiao/ZenithReborn.git
cd ZenithReborn
git config user.name "他的英文名或昵称"
git config user.email "他的 GitHub 邮箱"
pwsh -File checks/dev_setup.ps1 -LoaderRoot "D:/SteamLibrary/steamapps/common/tModLoader"
```

`dev_setup.ps1` 依次做这些事，全部幂等，可重复跑：

1. 校验 `<LoaderRoot>/tMLMod.targets` 存在（路径错会直接报错，不会半截失败）。
2. 把本机 tModLoader 路径写进仓库根的 `local.props`（**已 gitignore，永不入库**）。
3. 装 git 钩子（`checks/hooks/pre-commit` → `.git/hooks/`，钩子本身不入库，每个克隆都要装一次）。
4. 准备 `Luminance.dll`（从本机创意工坊的 Luminance 模组里提取）。
5. 编译一次（`-SkipBuild` 可跳过）。

前置：**.NET 8 SDK、tModLoader 1.4.4、PowerShell 7、Python 3**，Steam 创意工坊订阅 Luminance（workshop `3222493606`）。
PowerShell 必须是 `pwsh` 7；Windows PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按 GBK 读，直接解析失败。

验收：

```bash
pwsh -File checks/run_wood_checks.ps1     # 期望 PASS: 8509 focused checks，退出码 0，约 70–85 秒
```

项数是按启用套件**动态统计**的，会随夹具增删变化，不要把它当固定常数。

## 3. 路径不再写死（本次改动的核心）

以前换机器必须改三个**被跟踪**的文件，改完还不能提交——每次 `pull` 都跟本地改动打架。
现在三处统一按同一优先级解析：

```
环境变量 ZENITH_TML_ROOT  >  local.props 的 TmlRoot  >  默认 E:/SteamLibrary/steamapps/common/tModLoader
```

涉及文件：`ZenithReborn/ZenithReborn.csproj`、`checks/ZenithPrototypeCheck/ZenithPrototypeCheck.csproj`、`checks/run_wood_checks.ps1`。
临时切换（多版本 tModLoader 并存时）：

```powershell
$env:ZENITH_TML_ROOT = 'F:/tModLoader-1.4.4'; dotnet build ZenithReborn/ZenithReborn.csproj -c Release
```

`checks/` 下还有三十余个专项探测脚本（GPU 截图、材质实验室等）仍写死默认路径，只有换机的开发者会用到；需要时本机手改，**改完不要提交**。

## 4. 日常同步

```bash
git switch master
git pull --rebase                     # 先同步，再开工
git switch -c feat/wood-panel-fix     # 一个任务一个分支；名字用英文短横线，不加中文
# ... 改代码、写夹具 ...
pwsh -File checks/run_wood_checks.ps1 # 提交前至少跑一次全量
python checks/map_freshness.py        # 新增/删除文件、改版本号后必跑
git add ZenithReborn/WoodCrown.cs checks/ZenithPrototypeCheck/WoodCheck.cs   # 逐个点名，不用 git add -A
git commit -m "木质族：修复换剑后森林层数被清零"
git push -u origin HEAD               # 推分支，不推 master
```

然后到 GitHub 开 PR → 另一方看 diff → `Squash and merge` → 合完删分支：

```bash
git switch master && git pull --rebase && git branch -d feat/wood-panel-fix
```

用 `--rebase` 不用 merge：两人规模下线性历史更好读，出问题回滚点干净。
`pull --rebase` 若冲突，见 §7。

## 5. 冲突高发点（提前避开比事后合并便宜）

| 对象 | 为什么冲突 | 约定 |
|---|---|---|
| `build.txt` 版本号 | 两人同时升号必冲突 | **只有发布者改**，且只在发版那一刻改；功能分支不动版本号 |
| `docs/FILE_INDEX.md`、`docs/CODEBASE_MAP.md`、`docs/HOTSPOTS.md` | 索引/生成物，两边都加行 | 冲突**不要手合**：`python checks/build_file_index.py` 重生成 + 手工校正 `CODEBASE_MAP`/`HOTSPOTS` 的条目 |
| `SoulItem.cs` / `SoulUI.cs` / `SoulBlade.cs` | 三个已超载的大文件，谁的活都可能碰 | **同一时段只一个人改**，改动前在群里说一声；能新开文件就别往里塞 |
| `checks/ZenithPrototypeCheck/Check.cs` | 新增断言都在这里登记 | 各自新开 `XxxCheck.cs`，入口只加一行注册（已有多例：`LivingParryCheck.cs`、`WoodCheck.cs`） |
| `ZenithReborn/*.cs` 同名文件 | 分工重叠 | 按模块分工（见 `docs/CODEBASE_MAP.md`），一人一个文件族 |
| `VfxLibrary/` 下大 png | 二进制无法合并 | 冲突时取任意一边，再让改图的人重传 |

## 6. 绝对不能提交

`artifacts/`（16 GB 构建/检查产物）、`*-profile/`、`*-playtest/`、`*/bin`、`*/obj`、`*.tmod`、`*.wld`/`*.plr` 存档、完整日志、反编译产物、`local.props`、`.env`/`*.pem`/`*.key`。

这些已在 `.gitignore` 里。新增「本机私有配置」时顺手补一行 ignore，否则第一次提交就把别人的环境带进仓库。

`git status` 里出现 `artifacts/` 或任何 `> 10 MB` 的新文件，先停下确认。

## 7. 冲突处理三步

1. `git status` 看清哪些文件冲突；**先判断是不是生成物**（§5 第二行），生成物直接重生成，不要逐行合。
2. 代码冲突按语义合，不许「全收我这边」——对方那段可能修的是 bug。看不懂就问，别猜。
3. 合完必须重新验证：`dotnet build` → `pwsh -File checks/run_wood_checks.ps1` → `python checks/map_freshness.py`，三条都过再 `git add <具体文件>` + `git rebase --continue`。

## 8. 几条容易踩的坑

- **换行符**：`.gitattributes` 已固定 `*.cs/*.md/*.py/*.ps1 text eol=lf`，工作区可以是 CRLF。**不要改 `.gitattributes`，也不要关掉 `core.autocrlf`**，否则整库换行翻转，一次提交 diff 上万行。
- **中文注释**是硬规则：注释中文、标识符英文。对方新写的英文注释要顺手改掉，否则 review 退回。
- **钩子不是共享的**：`.git/hooks` 不入库。对方拉完代码仍要 `pwsh -File checks/install_git_hooks.ps1`（`dev_setup.ps1` 已代劳）。
- **存档不进仓库**：`My Games/Terraria/tModLoader` 下的人物与世界永远不发。联机测试各自用独立 profile 目录。
- **不要两边同时跑全量回归**：`run_wood_checks.ps1` 会重建隔离 profile 与打包产物，同一台机器并行跑会互相踩（两台机器各跑各的没问题）。
- **证据分级**：隔离夹具 ≪ 图形客户端 ≪ 真实多人。只跑过夹具就别说「验证通过」。
