# 0.3.103：剑色明暗过渡与材质泛光

用户指出高光像刷了一层白色笔刷，要求用过渡色表现高光和暗部，让玻璃保持通透。本轮围绕表面着色修改，保留102的主体密度与覆盖度分离；Opacity=0.1、Metallic=0.25、Roughness=0，56项默认全开。

## 实现与归属

原路径在CPU刃色、刃缘高光、GGX高光核和P19中多次向白色混合，颜色容易被洗掉。屏幕泛光另外从背景亮度提取能量，即使材质自己没有亮部，明亮背景也能制造额外光雾。默认笔刷贴图本身主要调制覆盖度，不能把这些白色贡献统称为某一张贴图画上去。

- `SwordFlowPalette`专门负责从实际剑色生成暗部、中间调、亮部三个相邻色锚点，统一检查亮度顺序。无彩剑使用冷钢色阶。它不承担绘制、资源加载或调试状态。
- `SwordFlowMaterial`只提交这一份调色结果，撤下刃色向白色混合；不增加另一套真实材质参数来源。
- `ZRSwordFlow`用连续曲面法线、光向和GGX响应定位色阶，并以平滑插值形成受光过渡。暗部减少表面光能，透射背景仍然可见，不给整片主体再涂一层不透明暗色。面高光与细亮刃共享剑色亮部，不再叠加白色高光核。P19改为“高光亮色过渡”，保留原参数名、序号和开关兼容。
- P20仍开启，噪声只在0.88～1之间轻微调制高光，避免原0.35～1的浓淡把连续受光切成云斑。
- `ZRGlassScreen`只从表面缓冲提取材质自身亮部，按最大通道的超阈值比例扩散，保留颜色比例；背景不再充当泛光来源。真实当前帧反射仍保留，因此玻璃仍可反射明亮天空和物体。

没有修改生产贴图、刀光内缘、头部连接、连续UV朝向或战斗逻辑。与102源码归档核对，116项原文件保持，35项图像/原始数据资产保持；`SoulMaterialTrail`及`SwordFlowMeshBasis`逐字节相同。固定姿态法线/覆盖缓冲与102逐像素完全相同。

- 单独关闭环境反射、内部色流、自发光后，三剑高光各有9428/9873/9257个超过检查亮度的像素；这些像素全部满足色彩饱和度大于0.25，平均分别为0.896/0.745/0.636。原始线性能量缓冲和黑底正常显示图分别保存，不把原始缓冲当成最终显示效果。
- 亮背景、空材质表面下，泛光开关前后像素差为0；有绿色材质亮部时，泛光绿色增量大于红蓝增量之和。此项直接运行正式屏幕Shader。
- 主体密度0、0.1、1的法线/覆盖缓冲仍完全相同；主体0仍有30488个可见反光像素。低主体密度的背景响应5661866，大于主体1的2748005，保持通透语义。这是对照差值，不是透光率百分比。
- 实际提交主体密度0.1、生命周期1、金属度0.25、粗糙度0；粗糙度通道非零像素数为0；56项保持全开，8路已配置输入实际绑定。

同姿态黑底正常显示图中，接近中性白的亮像素从450降至0，可见像素总数31036→30933。该指标只适用于这组固定输入，不能外推为世界里不会出现白色真实反射。

中途`colored-gradient-0.3.103`只完成材质导图，新增泛光夹具使用BasicEffect时发生顶点接口错误，没有生成通过报告。最终改为SpriteBatch的标准屏幕顶点接口并重新原生构建，以`colored-verified-0.3.103`为准。首轮受沙箱日志权限阻止的引擎启动也不作为通过证据。
