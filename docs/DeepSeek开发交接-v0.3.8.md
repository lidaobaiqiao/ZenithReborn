## 用户已经确认的规则

### 伤害与攻击

主剑基础伤害由 `SoulItem.BladeDamage` 计算：

```text
max(1, floor(player.GetWeaponDamage(该寄宿剑) × soul.Potency))
```

- 附着起始效能65%，每个现行成长节点+4个百分点，永久复生后110%。详见 `SoulItem`、`SoulProgress.Milestones`。
- 每把剑保留自己的武器前缀、暴击、击退与飞行时长，不从别的强剑取平均伤害；物品面板的平均参考值不用于统一结算。
- 同一主剑对同一NPC局部命中冷却8帧；不同剑不抢这份免疫。附属特性的充能间隔另算。
- 一次挥臂有20/40/60/80/100%五个节点，每个节点最多生成一把真实剑影。寄宿不足5把时，每把只出一次，其余节点留空；下一挥臂接续轮换。
- 支援剑不单独出主剑，也不贡献其武器伤害；登记过的支援特性依实际主攻来源结算。

### 槽位、木质族与成长

| 存储索引 | 数组 | 是否独立攻击 | 开放条件 |
|---|---|---|---|
| 0～9 | Hosts[10] | 有效普通槽是 | 附着及按序Boss/魂芯解封 |
| 10～14 | SupportHosts[5] | 否 | 有效木剑种类1/2/4/6/8，依次开放 |
| 15～16 | ForestHosts[2] | 有效森林槽是 | 12种木剑在基础普通+有效支援中凑齐 |

- 普通第1槽来自友善王；后续为眼、邪恶Boss、骷髅王、肉山、三王、花、石巨人、教徒、月亮领主，具体累计Boss位/魂芯位以 `SlotProgression.cs` 为准。
- 木质12种：木、针叶、棕榈、红木、仙人掌、乌木、暗影木、灰烬、珍珠、王朝、阴森、仙灵。松木是节日限定，已排除。后3把为自定义剑；阴森剑基础伤害90、使用间隔18帧。
- 木质效果倍率按1/2/4/6/8/全套为1.10/1.20/1.35/1.50/1.75/3倍，阶梯是最终倍率，不累乘。
- 全套提供100最大生命及2个真实剑位；有效战斗每5秒+1层，60秒到12层上限，脱战逐层衰减。当前每层+3防御、+1%减伤、+0.5生命/秒，另有主剑增伤，详见 `WoodPlayer` 与 `SoulBlade`。
- 全套需12种同时有效寄宿，至少7普通+5支援；森林奖励槽不能反过来凑自身的开放条件。有效性用最小不动点计算，不允许暂停支援自举解锁。
- 未解锁/暂停槽仍保留武器，空手点击可取回。不要删除、自动吞物或改变既有索引。
- 12木+8种基础金属至少20把，超过现有17总槽，当前接受构筑取舍；不能未经用户确认就加槽规避。
- 完全复生需全部主线铭刻、6魂芯、10把天顶材料剑同时处于普通槽，完成后永久记忆，可自由换装。

### 六把肉后矿石剑

详见 `0.3.6-肉后三矿实装.md` 与 `HardOreTypes.Description`。钴3命中轻刃、钯金5命中受限回血、秘银4命中导刃印、山铜三花瓣、精金对30防以上目标+12%来源伤害、钛金4命中环绕片。

- 充能按持有者/剑魂/特性/来源主剑/敌人主体区分，30帧最多计一次，180帧断连清空；触发冷却分来源。
- 附属伤害D是该来源主剑射出时的基础伤害快照；附属攻击不递归充能，不再次套成长倍率。
- 钯金回血有滚动6秒额度、吸血资源、缺血量和月噬禁疗限制，不能为“体验好”悄悄移除这些边界。
- 虫体按主体计数，敌人槽重用不能承接旧印记，取下来源应及时失效。

## UI的关键教训

输入与绘制有不同坐标前提：PostUpdateInput使用物理屏幕单位，先换算到UI单位；GameInterfaceLayer.Draw已变换过鼠标/视口，不能再除UIScale。

0.3.8的顺序是：PostUpdateInput捕获左右键和边沿 → 隐藏世界动作触发 → 原版底层界面看不到点击 → 仅前景剑魂层恢复 → 随后再遮蔽 → 全部界面结束后恢复物理状态，保留已消费状态。

空白/标题/禁用按钮也属于面板。按下后拖出或关闭，要捕获到松开；面板外仍能使用背包。不要改成“窗口打开就禁用一切鼠标”，否则无法拿起武器寄宿。滚动裁剪和SpriteBatch状态必须成对恢复。

## 构建、检查、打包

在仓库根目录执行：

```powershell
dotnet build ZenithReborn/ZenithReborn.csproj -c Release --nologo
pwsh -NoProfile -File checks/run_wood_checks.ps1
# 只导出包，不替换正式模组：
$env:ZENITH_PACKAGE_ONLY = '1'
python checks/package_install.py
Remove-Item Env:ZENITH_PACKAGE_ONLY
```

- 本机两份csproj导入 `E:/SteamLibrary/steamapps/common/tModLoader/tMLMod.targets`。另一台电脑需修改生产/检查csproj的Import，以及检查脚本的loaderRoot/dotnet路径。
- `run_wood_checks.ps1` 自动创建输出目录，编译生产与检查DLL，用tModLoader打包，再在独立 `wood-check-profile` 无窗口加载。测试模组最后会写PASS并退出。
- `artifacts/wood-check.txt` 为摘要；构建/打包/加载日志也在artifacts。脚本名沿用木质阶段，内容已覆盖更多模块。
- `package_install.py` 校验包内DLL/源码与当前工程、报告通过及时间关系；只打包模式请保留上面的环境变量。默认模式**会安装**，正式profile路径是本机专用，换电脑先改路径，不应盲跑。
- `stage-one-playtest` 图形夹具需自行创建隔离人物与世界；不会随仓库带入个人存档。`ZENITH_UI_GUI=1` 只在该隔离profile初始化演示库存；检查模组不能留在正式启用列表。
- 不要把无窗口全局状态检查放到与客户端输入同时竞跑的加载线程。夹具中的少数图形/客户端配方刷新替身只是为了隔离无窗口依赖，不能据此宣称对应画面或配方实测通过。
