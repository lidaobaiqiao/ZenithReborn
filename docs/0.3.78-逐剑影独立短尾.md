# 0.3.78：逐剑影独立短尾

本轮按`需求-天顶飞剑拖尾与剑影形态.md`处理普通剑魂主飞剑，不修改武技或矿石H4。

## 根因

0.3.77只把剑影采样改回15/30/45，材质仍铺满60个历史点。原版的连续网格使用其自身颜色与Shader，不能因为复用了原版点数，就认为自有玻璃材质也会形成同样的视觉分离：连续三角形仍然跨过全部间隙。剑影还额外乘了0.55，而底下的材质没有匹配这一层衰减，因此剑影相对带面更不明显。

第二条实际路径是`SoulTrailEnding`：运动阶段60时把完整历史复制成一整片，并关闭父弹幕的材质绘制。即使活动期分开，只改`DrawRibbonShader`也会在收尾重新变回整片。

## 修改

- `SoulTrailUnits.cs`集中定义本体及三个剑影：头点仍为0/15/30/45；尾部窗口为13/11/9/7个采样点，即覆盖12/10/8/6个更新间隔，分别留下3/5/7个间隔后才是下一剑影。没有删减三个剑影，也没有修改其历史位置、方向和旋转偏移。
- `SoulBlade.DrawRibbonShader`只提交各单元的独立窗口，不补画窗口之间的三角形；剑影和所属短尾共用0.75/0.50/0.25及`SpriteVisibility(phase-j)`窗口。本体保持原有贴图与配色，撤掉剑影额外的0.55衰减。这里的“亮度一致”指同一单元共享相对衰减因子，玻璃Shader的反射与贴图像素不是相同材质。
- `SoulMaterialTrail.BuildLayered`继续使用现有连续历史与CatmullRom平滑，允许短单元直接采用完整头宽；初始出现由既有时间窗控制，避免短距离窗被全局成长因子压得不可见。没有重新计算或凭空补圆形轨迹。
- `SoulTrailEnding`逐单元捕获、逐单元侵蚀。正常本体最多36帧，三个剑影依次18/12/9帧；提前回收依次24/20/16/12帧。剑影仍可见时跟随它的同一个历史头点，之后停留在最后位置收尽。旧剑影更早消失，避免多个冻结短片在归鞘处叠成一团；父弹幕销毁不截断余迹。
- 修正已有的四区遮罩加载线程问题：`ZoneMask.zrdata`原先在加载线程直接创建`Texture2D`，实际日志报`ThreadStateException`，导致四区数据没被挂上。现在在主线程上传，保留原始RGBA及原文件，卸载后过期队列不会重新挂资源。没有重新制作、重新导入或修改素材。

全部代码注释为中文。攻击、伤害、碰撞、更新速度、发射/返回时序、存档及槽位未改。仍使用项目自有`ZRSwordFlow`和原有屏幕合成，没有增加第三方材质或运行依赖。

## 验证入口

1. `pwsh -NoProfile -File checks/run_wood_checks.ps1`：原生编译及完整引擎回归，包含四个头点、窗口递减、严格留白、共享亮度/时间窗、三角形数与完整网格空间间隙检查。使用tML自带编译器，不通过损坏的NuGet还原，也不复用旧bin DLL。`native-build-check.json`将检查绑定到实际加载包。
2. `pwsh -NoProfile -File checks/run_soul_flight_world.ps1 -TimeoutSec 240`，以及`-Surface`：三剑真实AI、直接命中、返回、父弹幕提前销毁后余迹清零。重点查看24/27/30及42/48/54/60帧。对应法线/覆盖蒙版另存为`refraction-mask-042.png`等，可核查间隙处确实没有材质覆盖。
3. `pwsh -NoProfile -File checks/run_soul_input.ps1`：专用隔离客户端，启用ZenithReborn、HEROsMod、ImproveGame、SilkyUIFramework及检查模组，等待真实鼠标点击。检查模组不代替鼠标发射；输入、松开、原有ItemCheck及结束记录见`input.json`。`make_soul_input_evidence.py`导出按60游戏帧/秒排列的原速视频与明确标注的慢放。
4. `make_unit_trail_evidence.py --baseline <旧包路径>`：核对当前包与0.3.77随包资源逐字节保持、武技及矿石源码保持，检查生产世界蒙版连通区域，输出单剑原速视频/两倍慢放/关键帧。连通区域仅是覆盖证据，不是美术通过；飞剑真实轨迹交叉处允许物理重叠。

所有人物和世界均来自旧隔离档，不加载正式存档。GPU截图读回会拖慢夹具墙钟时间，原速片按游戏帧排列，不能用墙钟耗时评估帧率。技术检查与视觉验收分开；未测自然长时间游玩或真实多人，不认定历史超级训练假人黑屏已修复。最新数值、包身份和安装状态见`artifacts/install-result.json`及本版报告。

安装时发现正式启用表还增加了UpgradableZenith，本次鼠标测试未包含它；安装记录中的`isolated_mouse_soul_flight_full_mod_set`为false，不能称完整正式组合已测。正式启用表、其他模组与设置未改。

## 本轮完成结果

8371项引擎通过；默认/分区材质的三剑真实AI、直接命中、返回及父弹幕销毁后余迹收尽均通过。实际鼠标点击生成两把主飞剑，共创建八个单元余迹，松开后按原生时序完成，最后无飞剑或余迹残留。四区遮罩1024×1024已在主线程成功加载。

与正式0.3.77比较，全部41项Assets条目字节一致，17份武技/矿石/H4相关源码一致。生产默认蒙版在第42/48帧具有三个彼此分离的主要区域，第60帧仍保留两个分离的结束区域；初次方案第60帧曾叠成一个区域，因此本轮将旧剑影结束寿命递减并重新跑完上述验证。此数量受时间窗与真实轨迹交叉影响，不能要求每一帧永远四片。
