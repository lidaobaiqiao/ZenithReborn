# 0.3.14 · 飞剑表现与可拖动窗口

## 使用

打开剑魂窗口后，空手按住标题栏左键拖动。位置在当前世界游玩期间记住，关开窗口不重置，退出世界恢复默认；关闭按钮及页签不作为拖动区，手上拿着武器时也不会误拖。窗口始终夹在可视区域内，缩放/分辨率改变后仍可触及标题栏。

## 表现

- 矿石飞剑在原20帧成形期内平滑渐显并略微放大，增加很小的剑尖闪点。
- 冲刺时显示短而收尖的双色细拖尾、逐渐减淡的剑形残影；成形轨道不连接进冲刺拖尾。
- 冲刺及命中产生少量材质配色粒子，保持普通透明混合；不引入全屏闪光、放大光柱或爆炸光圈。
- 主剑维持原曲面轨迹、各剑颜色，只调整残影衰减及剑尖粒子漂移。命中次数、判定、伤害、范围和0.3.13出剑节奏不变。

## 实现与验证

- `SoulUI.PostUpdateInput`：转换一次物理坐标后处理拖动，并将旧面板、新面板及整次拖动交给原`SoulInput`捕获。松开后恢复窗口外操作，不退回Draw阶段才拦截。
- `SwordFlightTrail`：每个飞剑最多8点历史，渐隐末端为透明；距离断点或非有限值会清空轨迹，避免连到屏幕远处。
- 细拖尾与剑尖闪点显式采样1×1像素源区域，不能把整张MagicPixel纹理直接乘以像素长度，否则会放大成长光条。
- `WindowDragCheck`：真实输入钩子覆盖多种UI缩放、拖动/释放/出界/重开/缩小窗口/关闭按钮/持有物品；原UI检查继续覆盖实际背包处理程序的点击隔离。
- `RibbonCheck`增加短拖尾缓存、衰减、断点和渐显检查；完整隔离引擎2708项断言通过。生产模组编译0警告、0错误。
- 图形客户端与真实多人验证单独记录；源代码、引擎检查不等同于多人实测。

图形边界：原生自动化拖动在游戏一帧内完成，记录仅捕捉到正确的按下/释放而没有中间位移，未声称完整的OS连续拖动测试。另用20个渲染帧的测试夹具调用生产拖动处理器，确认面板实际移动、页签和关闭按钮位置同步；连续位移与跨缩放捕获由引擎检查覆盖。测试夹具只在隔离profile显式启用，正式配置不加载。

最终包在隔离客户端加载并调用了飞剑绘制；静帧检查发现整张像素纹理被放大的光条问题后，已改为显式1×1采样，重新编译、运行2708项引擎检查并加载修正包。未声称全流程视觉游玩、完整命中粒子捕捉、连续OS拖动或真实多人测试。对应包哈希和边界见`artifacts/ui-validation-0.3.14.json`。
