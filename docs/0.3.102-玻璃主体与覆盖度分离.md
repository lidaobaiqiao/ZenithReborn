# 0.3.102：玻璃主体与覆盖度分离

用户指出101不透明度0.1后整张特效消失，要求的是玻璃质感。问题确实在合成模型：此前只核对常量和GPU输出，没有验证“主体透明时表面反射仍存在”的行为合同。

本轮保留用户设定：主体Opacity0.1、Metallic0.25、Roughness0，56项仍全开。没有把数值调回1，也没有更换贴图或重做网格。

## 原因与修订

旧链路先在`SwordFlowMaterial`把Opacity乘入整张带面的生命周期Alpha，法线和表面缓冲因此都只剩十分之一；最终`ZRGlassScreen`又把它乘到覆盖度和泛光。低值时覆盖度还会再被smoothstep压低，实际效果接近整层消失。

现按已有职责修正：

- `SwordFlowMaterial`提交独立的生命周期覆盖和`uBodyOpacity`。`GlassOptics.BodyOpacity`是明确的光学输入，旧三/四参数构造和解构接口保持兼容，默认值仍来自唯一制作端preset。
- `ZRSwordFlow`的几何、形成、羽化、消融覆盖不再乘主体密度。主体密度控制吸收/透射与内部色流，不凭空新增常量自发光底色；反射、GGX、薄亮刃、自发光与消散前沿保持在表面层。法线/覆盖使用提前独立返回，避免未使用的体色通过lerp浮点抵消影响缓冲量化。
- P24内部色流此前也加进`reflected`，低主体密度时仍形成实色条带。现在归回主体颜色层，随主体密度变化；开关和强度参数没有被关闭或替换。
- `ZRGlassScreen`在完整几何覆盖上合成折射背景、主体密度及表面反光，不再使用全局Alpha抹掉整个玻璃。生命周期消散仍然独立生效。
- 原路径无真实背景时仍因P23开启而采白色占位，可能制造假反射。现在缺背景时不读占位；原生屏幕合成直接采当前帧执行SSR，保留原SsrStrength0.6及P23门控。

因此主体Opacity0表示没有实体底色，玻璃表面仍然存在；生命周期为0或完全消融时才整层退出。主体Opacity1则阻挡背景并保留表面反光。该语义与“材质表面存在在哪里”分别管理。

## 行为验证

最终GPU夹具为`TexturedSwordMaterialRenderCheck`，报告路径`artifacts/textured-sword-material/glass-verified-0.3.102/textured-material.json`。不再仅以写入Opacity常量作为通过条件。

- 主体密度0、0.1和1下，法线/覆盖缓冲逐像素完全相同。
- 主体0的黑底正常显示图仍有30631个亮度超过检查值的像素，反射和亮刃没有被整体抹掉；同时保留原始线性能量表面缓冲供检查。
- 精确暗/亮清屏背景的带面内部响应：主体0.1为5539799，主体1为2729125，前者对背景变化更敏感。此数值是对照差值，不是现实透光率百分比。
- 独立棋盘IOR对照仍使用`RefractionRenderCheck`，与主体密度的均匀背景合同分开。中途自绘棋盘诊断不作为最终透明度验收依据。
- 主体参数实测0.1，生命周期输入1，金属度0.25，粗糙度0；输出粗糙度非零像素为0。三剑配色、动画、逐图关闭、零生命周期覆盖和完全消融均检查。

两项目原生构建零错误、零警告，8426项引擎检查通过。49张实际GPU图像及正式五模组组合的白天/夜晚/局部光源隔离世界通过，各轮三剑实际命中、返回及独立消散完成，结束残余收尾为0；原生同帧IOR对照均通过且带面外变化为0。对应报告和精确包哈希统一记录在`artifacts/textured-sword-material/validation-0.3.102.json`。世界检查仍是受控发射，不是自然鼠标游玩或真实多人。
