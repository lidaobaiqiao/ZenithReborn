# 0.3.73 四区遮罩走原始数据 + 天顶两张贴图重做

## 一句话现状

接手 0.3.72 未完成的部分：四区遮罩在 0.3.72 里**只有磨损区真正生效**，现改为原始 RGBA 直接上传，四区同时生效；顺带重画了遮罩和天顶专属的两张贴图。包已部署（0.3.73，7.79 MB @ 20:40）。**未做游戏内验证，美术待用户判断。**

---

## 根因

0.3.72 的 `SwordFlowMaterial.cs` 用 `ModContent.Request<Texture2D>` 加载 `ZoneMask.png`。tML 的 `ImageIO.ToRaw` 会把 Alpha=0 处的 RGB 清空，而这张图的 A 通道本身就是"磨损区"数据——A 通道 93% 的像素为 0，于是这些位置的 R/G/B 一并被清零，刃口、脊线、腹部三区读出来全是黑。

这个坑在 `docs/0.3.69` 第 67 行已经记过（"只有 A 区能生效"），当时的解法是 `.zrdata` 原始 RGBA 直接上传，实现还留在 `SurfaceMaterialRenderer.cs:58-69`。0.3.72 重新走回了 PNG 常规加载。

实测数据（`checks/make_zone_mask.py` 之前对原图的统计）：

| 项 | 原图 |
|---|---|
| 四通道中间调（24~232）占比 | R/G/B/A 全部 **0.0%**，纯二值 0/255 |
| A 通道非零占比 | 6.8% |
| 四区在 depth 方向的分布 | 按满幅 0~1 画，但带面到 `depth≈0.82` 就没了，腹部近五分之一落在不可见区 |

二值意味着 shader 里 `zone.r*0.45` 这类权重是硬切的，四区交界必然是硬边——这不是"进游戏再判断"的事，图里已经写死了。

## 改了什么

**数据通路**（`SwordFlowMaterial.cs`）
- 新增 `TryLoadRaw`：读 `.zrdata`（魔数 ZRDT / 版本 1 / 宽 / 高 / RGBA 原始字节），`SetData` 直接上传，绕开图像解码对透明像素的处理
- `ZoneMask` 从常规贴图循环里移出，单独走原始数据
- 自建纹理登记进 `ownedData`，在 `Unload` 里随设备释放
- 遮罩缺失时打一条日志警告——否则四区失效是静默的，画面看起来"只是不太明显"

**四区遮罩**（`checks/make_zone_mask.py`，按带面真实几何重画）
- x 轴 = 沿剑迹的 s，y 轴 = 亮刃到暗侧的 depth，与 `tex2D(zoneSampler, float2(s, depth))` 对齐
- 四区落在 0~0.88 内：刃口 0~0.13、脊线中心 0.285、腹部 0.40~0.88
- 全部带羽化，中间调占比 R 7.2% / G 14.7% / B 15.7% / A 8.9%
- 强度沿剑迹起伏，不再是整条常数——整条一个值会读成"贴上去的红色色块"
- 磨损区是断续崩口 + 尖端离散斑块，不是一条连续亮线
- A 通道加 6/255 基底，即使将来有人用常规加载也不会整片清零

**天顶两张贴图**（`checks/make_zenith_maps.py`）
- `ZenithWear`：亮底 0.86 表示无磨损，上面压 70 条顺刃拉丝 + 45 个软边崩口。原图中位 130、崩口与底色对比不足，当磨损系数会让整片读成半磨损
- `ZenithField`：暗—亮—中三段沿剑迹铺开，峰值压到 0.76（原版中段几乎纯白，会把带面中段烧白），叠低频起伏避免"三根柱子"
