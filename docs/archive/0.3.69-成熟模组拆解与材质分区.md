## 成熟案例的重点

### 鬼切：素材角色少，时间和坐标分工细

实际`CrimsonSlashRenderer.BeginDraw`绑定256×128的SlashBrush01、512×512的NoiseSoft01；FX中有14处tex2D采样语句，复用两张图形成不同尺度/相位的变化。实际资源RGB并非逐字节完全相等，不能只凭“看起来灰”就丢弃其他通道。

方向笔刷提供长短、疏密和拉丝走向；噪声用于低频变形、局部撕裂和消散阈值。沿刃坐标、横向深度和生命期共同控制扫描前缘、刃侧存留、起笔端蒸发。扫掠、冲击和散尽各有节奏，几何姿态与时间驱动同源。

特别核对：本机0.9209方法名虽叫`DrawThreeLayers`，方法体实际只有主体与白热条两次`DrawLayer`调用。不能依据函数名/旧注释声称始终画了三层，更不能把“层数多”当作质感原因。我们仍用一个动态形状、一个底色体系、一次最终合成。

源码入口：[固定提交的调用方](https://github.com/hocha113/CalamityOverhaul/blob/8d2bd38f268239dab6f05f78061e732eb24b423a/Content/LegendWeapon/OnikiriLegend/CrimsonRendSlashs/CrimsonSlashRenderer.cs)。本机随包源码与网上当前提交分别保留，结论以所列样本为界。

### 灾厄Exoblade：同一噪声复用，不靠堆满PBR贴图

本机ExobladeSlashShader对同一噪声做三次不同频率采样，结合沿迹年龄、带面横向坐标产生亮刃/暗腹/消散。官方调用方用VoronoiShapes灰度图，颜色独立提交，并从挥剑进度构造连续轨迹。它没有靠一套AO/曲率/氧化图才达到这一斩击效果。

这说明成熟“能量刀光”与成熟“实体PBR表面”不是同一张检查表。我们需要吸收笔触尺度、区域分工、真实运动和生命周期这些做法，磨损贴图由具体武器设计决定。

参考：[官方Exoblade调用方](https://github.com/CalamityTeam/CalamityModPublic/blob/1a8cebd27ec5615316b78f71973446b5528d2b78/Projectiles/Melee/ExobladeProj.cs)。公开源码有自身[许可条款](https://github.com/CalamityTeam/CalamityModPublic/blob/1a8cebd27ec5615316b78f71973446b5528d2b78/LICENSE.md)，不把“公开可读”笼统称为MIT；本轮只作技术研究。

## 已实现的第一批改进

- `SurfaceMaterialDefinition.DetailLayers`有最多四层的范围/有限值检查；每层可调颜色、混合、频率、运动和局部粗糙度/金属度/自发光。
- `MaterialInheritance`正确继承/覆盖细节层列表，并验证最终结果。
- 通用Renderer真正加载Brush、Noise、LayerMask，并把数据交给自有ZRMaterialSurface。
- LayerMask的RGBA对应四层；精确区域遮罩生效时不再靠Threshold猜分区。它只调本片材质属性，不改动态形状、碰撞或额外画轮廓。
- 制作实验室0.1.1新增“分区示例”和“材质分区”贴图槽；读取、保存、导出和导入支持分区数据。Brush/Noise也可通过材质JSON指定并随导出保留。
- 默认武器绑定未批量改动，不把四区诊断图或示例配方自动分配给所有剑。

### 通道数据为何使用zrdata

tML的[ImageIO.ToRaw](https://github.com/tModLoader/tModLoader/blob/stable/patches/tModLoader/Terraria/ModLoader/IO/ImageIO.cs)会清空Alpha为0处的RGB。第一轮实际GPU检查中，原样PNG载入同样未保住这三种数据，只有A区能生效；失败记录保留于`artifacts/mod-vfx-research-20261024/first-region-failure.json`。最终改为原始RGBA直接上传，四区才全部通过。

载荷是16字节头：ASCII `ZRDT`＋小端uint32版本1＋uint32宽高，随后为逐行RGBA8字节。Loader校验版本、尺寸和完整长度，再SetData。不是新渲染框架，也不增加玩家插件。标量通道不做预乘、色彩变换或透明像素清理。

推荐美术先画四张灰度区图，用制作工具打包；不要依赖美术软件在Alpha为0时仍保留隐藏RGB。正常动态形状图仍走原有MotionMask，分类上LayerMasks为材质区域数据。

## 制作工具

`checks/review_mod_vfx.py`：复用既有归档读取器，核验容器、列出资源、按明确路径提取样本，记录哈希/尺寸/采样锚点。提取不执行模组。

`checks/audit_material_assets.py --output artifacts/material-audit.json`：记录工作区/已安装身份、贴图字节预算和两条Shader的声明/提交合同。词法扫描是辅助，不能替代GPU和调用链核对。

`checks/prepare_material_maps.py`：

```powershell
# 明确写出每个输入通道，工具不猜图的意义，也不静默缩放。
python checks/prepare_material_maps.py pack --channel R=edge.png:R --channel G=spine.png:R --channel B=body.png:R --channel A=wear.png:R --output regions.png
python checks/prepare_material_maps.py data regions.png --output regions.zrdata
# 独立实验室Input内用regions.zrdata，Assets.LayerMask指向该文件。
python checks/prepare_material_maps.py mips normal.png --kind normal --output artifacts/normal-mips
python checks/prepare_material_maps.py mips atlas.png --kind scalar --columns 4 --rows 4 --output artifacts/mask-mips
```

标量mip线性平均；颜色mip在线性光空间预乘后滤波；法线mip重归一化；图集逐帧烘焙，禁止混入邻帧。产物是离线候选，PNG文件本身不代表GPU已经具备mip链。高光方差补偿、阈值覆盖率保持、运行时LOD选择和各向异性仍待专门验证。

`checks/import_material_export.py`导入分区图时转换或保留原始载荷，分类到`LayerMasks/SwordTrail/实际剑名`，继续支持先预览操作、再写入源码及备份。隔离目录导入已验证，不修改正式武器绑定。
