# 0.3.34 支援 S6 归位与飞剑首击修复

日期：2026-10-21。基线：ZenithReborn 0.3.33。范围：只修 UI 支援槽位置与矿石飞剑首击收集，不改伤害公式、槽位容量、传奇槽规则或支援机制。

## 1. 第六个支援槽归位

- 现状：S6（索引 25）走 `SoulUI.SlotBounds` 的 `index>=25` 分支，被画到右下角独立列；与 S1–S5 的支援弧脱节。
- 修复：先判断 `SoulItem.SupportOrdinal(index)>=0`，所有支援槽（S1–S11）统一按当前 `SupportCapacity` 在原有支援弧上计算：
  - 数量 1：48°；
  - 数量 >1：`8° + ordinal × 80°/(count-1)`；
  - 半径仍为 `RingRadius+62`，节点仍 44。
- 数量 6 时位置为 8/24/40/56/72/88°，S6 直接在原弧线末端，不再去右下角。
- 旧扩展 17–24 仍只走旧物取回页；传奇槽 34 的右上特殊位置不变。

## 2. 飞剑每把主剑首击

旧逻辑在 `OreFamily.OnMainHit` 里有同魂/同目标 10 帧全局冷却，并且 `TriggerEligible`/`Materials` 使用 `TraitMains`（受“切换”诅咒限制为首把主剑）。结果一轮里只有前两把能进入积攒。

修复：

- `TriggerEligible` 改为检查全部 `soul.Active` 主剑，不再被“切换”诅咒裁掉非首把主剑。
- `OreItems` 使用 `Active + TraitSupports`：所有主剑都可首击积攒；支援仍受“切换”诅咒/结构规则约束，避免绕过支援战斗限制。
- 移除 `OnMainHit` 的 `LastGlobal`/`LastTarget` 10 帧门槛。
- 仍由 `SoulBlade.TryConsumeOreHit()` 保证**每把主剑只消费一次**；后续帧伤不补触发，飞剑自身/折返/巨剑不再递归。
- `OreSystem` 的编队、齐射、目标身份、超时释放和全收集巨剑逻辑不变。

## 验证

- 更新 `OreCheck`：同帧两把不同主剑各自产生一把飞剑；同一把主剑后续帧不再重复。
- 更新 `OreRewardCheck`：切换诅咒不再阻止非首把主剑的飞剑首击；支援战斗特性仍受诅咒抑制。
- 全量 `7964` 项通过。
- 未验证：图形客户端中 S6 实际弧线位置/点击、飞剑一圈数量观感、真实多人。

## 边界

- 不改 `SoulSupport` 的容量与奖励累加规则；只改支援槽 UI 坐标。
- 不改矿石飞剑伤害、速度、150% 基础、阶梯/全收集加成。
- 之后若做“每个数量一套 UI”，仍应复用本条支援弧公式，不重新发明布局。
