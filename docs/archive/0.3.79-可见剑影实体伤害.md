# 0.3.79：可见剑影实体伤害

用户已接受0.3.78外观，要求三个残影也有伤害。本轮只增加实际剑影的实体碰撞，保留现有材质与短尾，不继续调整美术。

## 伤害规则

本体仍在原运动阶段60停止伤害。十五、三十、四十五次更新前的三个剑影，按当前画面相同的姿态、亮灭时间窗与0.02可见阈值判定碰撞；尚未出现或已经消失的剑影不参与。使用各自历史中心和旋转，沿用原飞剑的剑形碰撞长度、宽度、来源缩放及厚重加成，不把整条材质短尾变成伤害区域。

剑影命中使用这把飞剑已有的完整伤害、暴击、击退和来源武器，不因亮度变暗而打折。本体及三个剑影共用同一弹幕，因此同一NPC仍受16子更新（8游戏帧）局部免疫，诅咒的每目标直接命中次数上限也共享。不同目标可以各自被不同剑影打中。新增实际可命中位置和阶段会增加攻击覆盖及伤害机会，不能称为纯视觉改动。

所有命中仍走原有ModifyHitNPC/OnHitNPC和SoulSource流程，归属同一Sword/SoulId；不复制新伤害弹幕。矿石首击、环境首击与接力等一次性状态仍附在原父飞剑上，剑影不会重复获得新首击资格。提前归鞘立即停掉所有剑影伤害；剩余拖尾、独立消散片与碎光不追加伤害。

## 实现

- `SoulBlade.BodyCanDamage`单独表达原本体窗口，`CanDamage`再纳入可见剑影。
- `TryGetEchoPose`作为绘制与碰撞共用入口，读取原0/15/30/45布局，不改剑影数量、朝向或采样间距。
- `Colliding`先查本体，再查三个可见剑影，复用同一剑形碰撞计算。
- 历史姿态记录移出客户端视觉分支：无显卡/专用服务器同样可查询剑影；贴图、声音、粒子和消散缓存仍只由客户端处理。网络字段、发射轨迹、伤害公式、存档和槽位不变。

## 验证

`checks/run_wood_checks.ps1`运行完整引擎回归。新增`EchoDamageCheck`在无显卡路径形成三个真实历史剑影，再通过原版`Projectile.Damage()`验证三处分别扣血、完整伤害一致、同目标共享免疫、空隙无伤害、矿石首击不重置、诅咒上限与提前回收/熄灭停伤。原版轨迹对照仍验证本体阶段60停伤，不再用旧的“阶段60后整个弹幕完全无伤害”断言否定用户此次需求。

`checks/run_soul_flight_world.ps1 -EchoDamage -TimeoutSec 240`在隔离世界执行真实Projectile.Update与NPC命中回调。夹具将三个40×40测试敌人安排在三个剑影位置，未命中时跟随历史头点；只安排目标位置，不手动扣血。报告须包含三个剑影的命中，且本体碰撞为false，记录本体与NPC距离、剑影与NPC距离、阶段和实际伤害。它是受控世界夹具，不是自然游玩或多人证据。

未测试真实多人或完整正式模组组合；不能把无显卡服务端路径/服务端模式的状态查询检查称为多人实战通过。正式人物世界不参与验证；只备份替换ZenithReborn目标包。
