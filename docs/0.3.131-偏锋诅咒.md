# 0.3.131：偏锋诅咒

> 状态：机制已实装，参数（48 / 24 像素）待实战手感测试。
> 设计来源：用户下发的《偏锋诅咒设计文档》（机制确定、参数待实战测试）。
> 图形客户端、自然操作、真实多人未验证。

## 一、设计定义

**偏锋（Deviation）**：干扰天顶剑攻击精度的灵魂诅咒。每把飞剑的目标位置获得独立、稳定的随机偏移；最大偏移 48 像素，击败克苏鲁之脑后降为 24 像素，再击败拜月教邪教徒后归零。

> 剑锋失准，而非剑锋失控。

偏锋只改目标位置，不动伤害、攻速、出剑数、命中次数、地形穿透、武器特性与飞剑运动方式。

## 二、替换了什么

| 项 | 原「切换」 | 现「偏锋」 |
|---|---|---|
| 负面效果 | 未解除时只认第一把主剑特性 | 飞剑目标位置独立随机偏移 |
| 武器特性 | 被压制 | **全部正常触发**（`TraitEnabled` 恒 true） |
| 用户可见名 | `Names[1]="切换"` | `Names[1]="偏锋"` |
| 祝福 | 百刃接力 | **不变**（`Blessings[1]` 仍为「切换」） |
| Boss 绑定 | 克苏鲁之脑 → 拜月教邪教徒 | 不变 |

`OreFlightMains` 的「未解除时百炼飞剑前 4 把计入矿材」按用户 0.3.37 定稿**保留**（设计稿未点名，不属「特性限制」）。

## 三、关键实现决策

### 1. 保留枚举整数，零风险兼容旧档

`SoulCurse.Switching` 标识符与整数值 **1** 全部保留，只改显示名。原因：

- 存档只持久化 `Seals`（Boss 位掩码）与 `LegacyReleased`（按 `1 << (int)curse` 的位），不存枚举名或枚举整数。
- `Groups` / `Names` / `Blessings` / `BossNames` 全按整数索引；`AllReleased=63` 与 `curseSchema=1` 是 6 位定长。
- `SoulBossUnlocks.cs:65` 用 `Enum.TryParse` 解析 UI 键 `curse-Switching`，改名会打断键。
- 新增第 7 个枚举成员会破坏上述全部定长结构，故不新增。

### 2. 三档按个人 Boss 记录数，不按 CurseStage

`Groups[1]=[Brain, Cultist]` 只有两位 Boss，`StageForCount(count, total=2)` 的 `count=1` 先命中 `count>=total-1` 直接判 **Released**，`Weakened` 永不可达。若按 `CurseStage` 写 48/24/0 三档，中间档永远取不到。

故 `SoulDeviation.MaxOffset(soul)` 按 `SoulCurses.Count(soul, SoulCurse.Switching)` 分三档：0 → 48、1 → 24、≥2 → 0；`LegacyReleased` 该位为 1 时直接返回 0（旧档已解除，不重新上诅咒）。**不改 `StageForCount`**，其他五道诅咒与 Boss 进度规则不受影响。

代价：UI 阶段标签仍走原 6 诅咒规则（本组 count=1 显示「已解除」），而偏锋此时仍有 24 像素偏移。两者口径不同是有意为之，版本号不改、Boss 进度不改的约束下没有更干净的表达。UI 阶段说明通过 `SoulDeviation.MaxOffsetAt(stage)` 取同一组常量，不另写一份数字。

### 3. 独立 `CurseOffset` 字段，不动运动系统

`SoulItem.EmitBlade` 生成飞剑时调用一次 `SoulDeviation.NextOffset(soul)`，写入 `SoulBlade.CurseOffset`；AI 里仅把 `target` 改为 `player.MountedCenter + velocity + CurseOffset`。

没有把偏移加进 `TargetOffset`：`velocity = TargetOffset * .5f`，其 `Length()` 会改变飞行步长 `step`、椭圆半径、粒子数量与特技朝向，违反「不改变运动速度」。

随机分布按设计稿：`radius = Max × (0.35 + 0.65 × sqrt(u))`，角度 0~2π，`Main.rand` 取一次。每剑独立、飞行期间固定、实例结束即失效。

### 4. 多人同步复用现有机制

`EmitBlade` 只在拥有者客户端生成弹幕，末尾已有 `netUpdate = true`。`CurseOffset.X/.Y` 追加到 `SoulBlade.SendExtraAI/ReceiveExtraAI` 末尾（读写顺序对称），`Reset()` 清零。其他端只读回、不重新随机 → 两端一致、无重复叠加、无每帧抖动。

## 五、待实战调整

48 / 24 像素与 `0.35+0.65√u` 分布是设计稿给的第一版参数。若因原生攻击覆盖范围较大而难以察觉，优先调参，不改机制。
