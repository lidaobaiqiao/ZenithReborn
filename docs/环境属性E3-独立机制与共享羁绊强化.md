# 环境属性 E3 · 独立机制与共享羁绊强化

日期：2026-10-21。用户确定新的设计方向：每个环境提供独立机制；激活环境越多，每个已激活环境的机制都同步享受当前层级的羁绊增幅。

## 已确认的核心规则

1. 环境机制独立设计，各有基础效果，不把21种环境做成同一个效果的不同颜色。
2. 以实际已激活的环境集合确定统一羁绊层级。
3. 当前层级强化全部已激活环境，而不只是新激活的那个环境。
4. 用户示例：激活十重环境时，这十种环境各自的机制均享受十层羁绊中定义的属性增幅。
5. 环境属性继续与种族、单剑特性并行叠加，既有木质和矿石身份不被替换。

| 当前激活情况 | 环境自身机制 | 共享强化 |
|---|---|---|
| 激活1种环境 | 该环境自己的机制 | 使用1种激活环境所对应的羁绊档位 |
| 激活4种环境 | 四种各自独立的机制 | 四种均使用当前共同档位 |
| 激活10种环境 | 十种各自独立的机制 | 十种均获得十层档位规定的强化 |

十重是用户解释机制的例子，不预设环境上限为10。具体档位是否连续、每档如何增长、最高档和全收集奖励均待设计。

## 后续实现应表达的关系

设A为按最终激活规则得到的不同环境集合，N为A的数量。共享羁绊由N决定，每个e属于A的环境分别结算：

`环境e的最终机制 = 对环境e的基础机制，应用当前共享羁绊档位规定的强化`

共享的是当前档位和强化规则；各环境的机制、基础数值、计时、触发记录及效果来源仍独立。加成是如何影响伤害、持续时间、范围、层数或其他参数，需在各机制设计中明确，不能把所有参数一概相乘。

同一环境若由多把剑提供，应在环境集合中以环境ID识别；多把剑的具体激活贡献、机制来源或叠加强度另行设计，不能擅自把同环境重复武器直接当成多个不同环境。

若后续档位包含玩家全局属性，应单独说明其叠加和结算规则；本轮未决定这些数值是共享一次还是按环境分别提供，不能混同于已经确认的“每个独立机制都享受当前档位”。
