# 新种族设计草案：召唤出战武器

状态：用户指定由不可见玩家代理使用寄宿武器，走原版玩家攻击通道；种族名称、成员和具体数值暂未指定。已做独立服务端发射试验，尚未接入战斗。

## 核心机制

激活此种族后，剑魂能够召唤其有效出战槽中寄宿的武器。每把召唤武器自动攻击，并以对应寄宿武器本体为行为来源，继承该武器的原版攻击和特殊效果。

例如，养蜂人要实际召出其蜜蜂，种子弯刀要产生其种子弹及后续行为；吸血鬼刀的吸血、回旋镖的飞行与回收、悠悠球的运行规则也需要针对各自机制核验。例子说明继承含义，不代表它们就是本族成员或目前已经获得支持。

种族不是互斥攻击模式：在满足各自激活条件时，新种族与木质族、矿石族、神圣天堂及以后其他种族的特性可以同时生效。天顶剑魂的现有攻击和已激活种族机制继续运作；新增召唤武器不应因切换所谓“攻击模式”而关闭其他种族。

“本体”在此特指寄宿武器本体，用户要求继承的是它的原版攻击及特殊效果。剑魂自身的剑影、种族效果、诅咒和祝福仍按现有机制运作；召唤武器的额外命中如何参与各项剑魂触发，需按每项原有触发规则判断和验证，不能简单把重复触发当作继承成功。

## 用户指定的实现方向：隐形玩家代理

召唤物负责自动寻找目标和移动；对应的不可见玩家代理持有该出战槽的寄宿武器，以玩家物品使用流程驱动攻击。优先由引擎和原武器自身的逻辑处理使用时序、近战命中、弹幕与武器特殊行为，避免逐把重新编写攻击。代理的武器实例需要保留来源和前缀；原版玩家本体与其他已激活种族继续工作。

玩家身份、弹幕归属、输入目标和命中回调是要验证的具体连接点：代理攻击产生的效果应归属于真实玩家，不得影响真实玩家的物品、位置或输入。对确实依赖真实玩家全局状态或特殊控制的武器，只在原版流程不足时进行必要兼容处理。多人同步也需独立验证，不能凭单人模拟下结论。

## 已完成的独立试验

在只加载隔离测试模组的服务端进程中，建立一个独立于 `Main.player[0]` 的 `Player` 对象，使其身份编号与玩家一致，分别持有四把原版武器并调用 `Player.ItemCheck`。星怒生成原版星弹 9；泰拉刃生成 984/985；吸血鬼刀生成 304；种子弯刀生成 483；生成的弹幕 owner 均为 0，四组没有抛出异常。日志和逐条数据见 `artifacts/player-proxy-probe/run.log`、`artifacts/player-proxy-probe/result.json`。

该试验只证明隔离条件下的玩家使用流程能够产生这四类原版弹幕；还没有制作可见或不可见召唤物、自动寻敌、剑魂寄宿接入，也没有验证近战实际命中、吸血、前缀/装备、不同模组或联网。不能把它称为整套种族功能或全部武器继承已完成。

## 待确定

1. 名称、成员与激活条件：用户暂不列出。
2. 召唤武器何时出现、离场，是否需要持续攻击或持有剑魂；是否同时召出所有有效出战武器。
3. 自动攻击的目标选择、距离与攻击间隔，以及不同攻击形态如何表达。
4. 基础伤害、攻速和剑魂成长如何与原武器使用属性结算；具体数值尚未指定。
5. 各种召唤攻击与剑魂自身机制的触发归属、共享冷却和命中次数，避免破坏已确定的其他种族效果。
6. 玩家切换武器、取回寄宿物、死亡或离开战斗时的生命周期，以及多人同步。

## 与当前实现的差距

当前 `SoulSwingPlayer` 按出战槽调度 `SoulItem.EmitBlade`，发射携带来源类型和槽位的 `SoulBlade`，使用天顶剑式轨迹。`SoulBlade.ReleaseWeaponSpecial` 只为部分天顶材料武器手工释放特效，不能由此推出所有寄宿武器的原版攻击、命中及物品钩子均已继承。新种族以用户指定的隐形玩家代理调用原版物品流程，通过明确接口接入现有出战槽和种族机制；不能用现有特效入口冒充完整实现。

## 验收原则

根据最终确定的触发规则，选取普通近战、原版弹幕、命中特效与治疗、持续控制和多阶段攻击等代表武器，比较原武器与召唤武器的实际行为；再测试多族同时激活，确认各自现有特性仍按规则生效。逐项记录已支持、未支持和不兼容情况；技术夹具、实际游戏、多人及美术观察分开报告。
