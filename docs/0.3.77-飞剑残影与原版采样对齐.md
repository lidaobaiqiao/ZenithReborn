# 0.3.77 飞剑残影与原版采样对齐

## 问题

飞剑的剑影（残影）连成一条，看起来像连续的实心链条（用户描述为 `11111`），
而不是原版那样稀疏、彼此分开的几把剑（用户期望 `1000100010001`）。

## 根因

用 ILSpy 反编译 `E:\SteamLibrary\steamapps\common\tModLoader\tModLoader.dll`
（Terraria 已合并进 tModLoader，没有单独的 Terraria.dll），拿到原版 `Projectile 933` 的真实实现，
逐值比对后确认：**我们和原版的采样步长差了 5 倍。**

原版参数（`Main.DrawProjDirect`，`type == 933` 分支）：

```csharp
num12 = 60;      // 循环起点索引
num14 = 60f;     // 缩放插值分母
num10 = 0;       // 循环终点（不含）
num11 = -15;     // ★ 步长 -15
```

对应循环：

```csharp
for (int j = num12; (num11 > 0 && j < num10) || (num11 < 0 && j > num10); j += num11)
{
    if (j >= proj.oldPos.Length) continue;   // j=60 越界 → 跳过
    ...
}
```

→ `j = 60, 45, 30, 15`，其中 60 越界被跳过，**实际只画 3 个剑影**。
这个 15 在原版里也写成常量 `FinalFractalHelper.FramesPerImportantTrail = 15`。

我们之前是 `for (int k = 0; k < trailCount; k += 3)`，约 20 个剑影、间隔 3 帧，
密度是原版的 5 倍，所以糊成一条。

## 原版完整规格（反编译所得）

### 历史缓存

`ProjectileID.Sets.TrailCacheLength[933] = 60`，`TrailingMode[933] = 4`。

mode 4 的写入逻辑：

```csharp
Vector2 val3 = Main.player[owner].position - Main.player[owner].oldPosition;
for (int num31 = oldPos.Length - 1; num31 > 0; num31--)
{
    oldPos[num31]            = oldPos[num31 - 1];
    oldRot[num31]            = oldRot[num31 - 1];
    oldSpriteDirection[num31]= oldSpriteDirection[num31 - 1];
    if (numUpdates == 0 && oldPos[num31] != Vector2.Zero)
        oldPos[num31] += val3;      // 玩家移动补偿
}
oldPos[0] = position; oldRot[0] = rotation; oldSpriteDirection[0] = spriteDirection;
```

索引 0 = 最新，索引越大越旧。`extraUpdates = 1`，每个游戏帧记录两个点。

### 剑影透明度

```csharp
float num20 = num12 - j;                                    // 15 / 30 / 45
val3 *= num20 / (TrailCacheLength * 1.5f);                  // 这步被下面的分支覆盖

if (proj.type == 933)
{
    float t = proj.localAI[0] - (float)j;
    float num25 = GetLerpValue(0f, 20f, t, true) * GetLerpValue(68f, 60f, t, true);
    float lerpValue2 = GetLerpValue(0f, TrailCacheLength, num20, true);
    val3 = Color.White * lerpValue2 * proj.Opacity * num25;
}
```

即 **alpha = (60 - j) / 60 × Opacity × 时间窗**：

| 索引 j | 年龄（update） | 年龄（游戏帧） | alpha |
|---|---|---|---|
| 15 | 15 | 7.5 | **0.75** |
| 30 | 30 | 15 | **0.50** |
| 45 | 45 | 22.5 | **0.25** |

近亮远暗，线性。

时间窗 `t = localAI[0] - j`：`t ∈ (0,20)` 渐入、`t ∈ (60,68)` 渐出。
所以剑影是**依次点亮、依次熄灭**，不是同时全亮：

| 相位 | 发生 |
|---|---|
| 15 | j=15 剑影开始亮 |
| 30 | j=30 开始亮 |
| 45 | j=45 开始亮（三个同时可见） |
| 75 | j=15 开始淡出 |
| 83 | j=15 消失 |
| 105 | j=45 开始淡出 |
| 113 | j=45 消失 |
| 120 | 剑本体 Kill |

### 网格拖尾

原版**确实有一条整条连续带**（`FinalFractalHelper.Draw`）：

```csharp
_vertexStrip.PrepareStrip(proj.oldPos, proj.oldRot,
    finalFractalProfile.colorMethod, finalFractalProfile.widthMethod,
    -Main.screenPosition + proj.Size / 2f, proj.oldPos.Length, includeBacksides: true);
```

- 吃满全部 60 个历史点，不做平滑
- 半宽恒定：`trailWidth = fullBladeLength / 2`
- 颜色：`trailColor × (1 - progress / 0.98)`，alpha 再砍半
- 天顶剑（物品 4956）的 profile：`new FinalFractalProfile(86f, new Color(178, 255, 180))` → 半宽 43，淡绿白

顶点沿「朝向 − 90°」左右各偏 `halfWidth`，V 坐标 0/1，U 坐标 = progress。**不是**给每个剑影各挂一小段。

### 绘制顺序

`Main.DrawProj`：先 `FinalFractalHelper.Draw(proj)` 铺带 → 再 `DrawProjDirect` 画剑影 → 再画剑本体 → 再叠一层白色放大稿（×1.25，alpha 127）和剑柄星芒。

## 本轮改动（`ZenithReborn/SoulBlade.cs`）

1. **剑影循环改回原版步长**
   `for (int k = 0; k < trailCount; k += 3)` → `for (int j = 60; j > 0; j -= 15)`，
   只画 45 / 30 / 15 三个，alpha = `(60 - j) / 60 × Opacity × SpriteVisibility(phase - j)`。
   顺带补上原版的时间窗：之前剑影没有按生命周期依次亮灭。

2. **新增 `trailDirections[]`**
   原版每个历史点都存 `oldSpriteDirection`。剑飞行途中会翻转朝向，
   旧剑影必须用它自己那一帧的朝向，否则镜像和旋转偏移都会错。

3. **网格拖尾从分段改回整条**
   `headCount = 18, k += 3`（6 段、每段 3 点）→ 单层 `(0, 60)`。
   分段正是之前"连成一团"的来源：6 段短带全挤在剑附近，各自重新渐入，互相叠加成一片。

4. **尾端补原版线性衰减**
   顶点红通道存的是轨迹年龄，用它把 alpha 乘上 `(1 - age / 0.98)`，
   对应原版 `StripColors` 的 `(1 - progress / 0.98)`。
   于是剑影越靠后，身下的带面越短越暗——这正是用户想要的观感。

## 未改动的部分

- **旋转偏移公式保持 `+Pi/4 * (1 - spriteDirection)` 不变。**
  它看起来和原版的 `-PI/4 * spriteDirection` 不一致，但我们的 `Projectile.rotation`
  存储约定本身就比原版少 PI/4（AI 里写的是 `orbit + aim + PiOver4`，原版是 `+PI/2`），
  两者叠加后屏幕角度一致。之前误判这是 bug，实际是自洽的。
